# 渲染与性能

这份文档说明 `Website-Nuxt` 为什么按页面使用不同渲染方式，以及首页性能和 SEO 落在哪。页面行为和接口与 `Website-Vue` 对齐。适用版本：Nuxt 4.5、Nitro `node-server`。

## 渲染分工

全站默认仍是服务端渲染。`nuxt.config.ts` 的 `routeRules` 只改「这一条 URL 怎么缓存、要不要在构建时生成」。

| 路由 | 方式 | 原因 |
|---|---|---|
| `/` | SWR 60 秒 | 落地页必须有 HTML。推荐和热门会变，构建时冻住会过期 |
| `/category` | 构建时预渲染 | 分类树很少变，爬虫和首屏都吃静态 HTML |
| `/articles`、`/essays` | SWR 120 秒 | 筛选组合太多，不能全量预渲染。查询串各自成一条缓存 |
| `/articles/:id`、`/essays/:id` | SWR 10 分钟 | 正文页是收录主体。第一次请求渲染，之后直接回缓存 |
| `/search` | 预渲染搜索壳，结果只在浏览器请求 | 关键词没有稳定收录价值 |
| `/download-guide`、`/open-miniprogram` | 构建时预渲染 | 静态说明，不打接口 |

没有用 ISR。Nitro 的 `isr` 只在 Vercel / Netlify 上写进 CDN。这个站是自建 Node，对着 `course_server`。`swr` 在 `node-server` 上就会缓存整页响应，并带 `s-maxage` 和 `stale-while-revalidate`。前面再加 Nginx 或 CDN 时，这些头可以直接用。

预渲染关闭了 `crawlLinks`。分类页链到大量文章，打开后会在构建时把详情页全部抓下来，和「详情按需缓存」冲突。

## 首页

首页 HTML 固定请求 `GET /api/v1/home`，不带 `grade`。年级存在 `localStorage`（键 `website_selected_grade`），只在浏览器 `onMounted` 之后读取。选中年级后另发 `GET /home?grade=`，不改变 URL。

这样做是为了让所有访客共用同一份可缓存 HTML。如果服务端读年级，SWR 会把某个人的年级页发给下一个人。

水合完成前，年级按钮保持「全部年级」，链接也不带年级参数，避免服务端 HTML 和客户端首屏不一致。水合之后再切到本地记住的年级。切换时保留上一屏，等新数据返回再替换，避免首页布局跳动。状态变化放在屏幕阅读器文本「正在按年级刷新」里。

首页标题用 `予初作文 · 小学语文作文资料`，并关掉全局的 ` · 予初作文` 后缀，避免标题重复。CSR 站的标题是 `首页 · 予初作文`。

## 性能

这些是为 Lighthouse 和首屏做的，不是另一套视觉：

- 首屏内容在 HTML 里。首页实测包含文章卡片标题，不依赖浏览器把列表补出来。
- 不加载 Google Fonts。字体栈把「宋体 / 苹方」放在 Noto 前面。CSR 站会下载 Noto Sans SC 和 Noto Serif SC，中文网页字体很大，而且样式表挡在首屏前面。本站在已安装这些系统字体的机器上观感接近；没安装时不会去拉一套完整中文字体。
- 首屏标题动画只做位移，不从 `opacity: 0` 开始。Lighthouse 不模拟「减少动态效果」时，从透明淡入会推迟 LCP。
- `prefers-reduced-motion: reduce` 时关掉首屏动画和页面过渡。
- 卡片图用 `width` / `height`、`aspect-ratio: 16 / 9`、`decoding="async"`。首屏推荐第一张传 `priority`，改成 `loading="eager"` 并注入 `fetchpriority="high"` 的 image preload；其余仍是 `loading="lazy"`。封面在首屏标题下面。
- 图片走 `@nuxt/image` + 自定义的 `aliyunoss` provider（`app/providers/aliyun-oss.ts`）。它只改写 URL，拼 `?x-oss-process=image/resize,.../format,webp`，不经过 Nuxt 代理，所以不会变成开放图片服务；白名单外的域名和本地 `/uploads` 原样返回。列表卡片另外给 `sizes`，把 srcset 从 3072w 收窄到实际显示档位。
- 文章列表、作文列表、搜索使用 `keepalive`，对齐 CSR 站的 KeepAlive。详情不缓存组件，换 id 会重新取数。
- Nitro `compressPublicAssets` 压缩构建产物：`/_nuxt/**` 带内容 hash，由 Nitro 发 `public, max-age=31536000, immutable`，并有预压缩的 `.br` / `.gz`。安全响应头加在 `/**` 上：`nosniff`、`Referrer-Policy`、`X-Frame-Options`、`Permissions-Policy`。
- SSR 动态响应（HTML、`/_payload.json`）的压缩在 Nginx，不在 Nitro。见 `course_server/deploy/ssr.vunbo.com.conf` 里的 `gzip on` / `gzip_proxied any` —— 少了 `gzip_proxied any` 等于不压，`gzip on` 白开。实测首页 HTML 27921B → gzip 5354B，payload 28552B → gzip 11194B。改完按 `update-runbook.md` 8.3 验收。

首页 SWR 有一个上限：失败的首次渲染也会被缓存，最长等到 TTL。见 `nuxt.config.ts` 里的 `ponytail` 注释。升级方式是只缓存 HTTP 200。

## SEO

每页通过 `app/composables/useSiteSeo.ts` 输出 `title`、`description`、canonical、Open Graph、Twitter Card。详情页额外输出 Article 和 BreadcrumbList 的 JSON-LD。`<` 会转成 `\u003c`，避免标题里的字符打断 script。

首页输出 WebSite 结构化数据。`html` 的 `lang` 是 `zh-CN`。

搜索页同时做三件事：HTML 里的 `noindex`、响应头 `X-Robots-Tag: noindex, follow`、`robots.txt` 的 `Disallow: /search`。搜索壳在构建时生成，所以 meta 在 HTML 里，不依赖浏览器执行脚本。检索结果不进这份 HTML，避免爬虫把每次查询当成落地页。

`/robots.txt` 和 `/sitemap.xml` 在请求时生成。sitemap 收录静态入口，再分页拉取文章和作文 id。不收录 `/search`。

sitemap 最多拉 20 页、每页 50 条。超过后会漏新内容，应改成 sitemap index。后端不可用时仍返回静态入口，不回 500。

详情页标题用文章或作文标题，不是 CSR 站写死的「文章详情」。

作文正文用 `v-html`。内容和小程序 rich-text 一样，来自后台编辑器，不是访客输入。

## 请求

浏览器请求 `/api/v1`，由 Nitro 反代到 `NUXT_API_ORIGIN`。服务端取数直接请求这个源站，因为 SSR 里没有浏览器那种相对路径主机名。

响应仍是 `{ code, message, data }`，`code === 0` 才成功。超时 15 秒。

`NUXT_PUBLIC_SITE_URL` 用于 canonical 和 sitemap。上线前改成正式域名，否则 sitemap 会指向本地地址。

## 验证

在 `Website-Nuxt/` 下：

```bash
pnpm test
pnpm typecheck
pnpm build
node .output/server/index.mjs
```

`pnpm build` 预渲染分类页时会请求 `NUXT_API_ORIGIN`。后端没启动时，这一步会失败。

已在本机对生产构建做过这些检查（`course_server` 在 `:8080`）：

- `pnpm test` 通过，`pnpm typecheck` 通过，`pnpm build` 通过。
- `GET /` 返回 200，`Cache-Control` 为 `s-maxage=60, stale-while-revalidate`，HTML 含 `h1`、推荐 / 热门 / 优秀作文标题、WebSite JSON-LD，且没有 `fonts.googleapis.com`。
- `GET /articles/13` 的标题是文章名，HTML 含正文摘要和 JSON-LD。
- `GET /articles?grade=6` 的缓存是 `s-maxage=120`。
- `GET /search` 的 HTML 含 `noindex` 和热门词，响应头是 `X-Robots-Tag: noindex, follow`。
- `GET /robots.txt` 禁止 `/search`，`GET /sitemap.xml` 含文章和作文 URL，不含 `/search`。
- 浏览器里切换六年级后，首页 URL 仍是 `/`，列表变成该年级内容。分类页、文章详情、小程序弹窗、搜索「我的植物朋友」可用。
